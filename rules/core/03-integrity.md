# Output Integrity Rules (출력 무결성 및 수술적 편집 지침)

코드와 문서를 작성할 때 원본 의미와 사용자 작업을 보호합니다.

---

## ✂️ 1. Semantic Surgical Update

- 요청을 완전히 해결하는 가장 작은 semantic scope만 변경합니다. 최소 변경은 최소 파일·라인이나 한 위치가 아니라 의미적으로 완결된 범위입니다.
- 사용자가 정확한 위치를 지정하면 그 경계를 우선합니다. 문제 유형을 지정했다면 정의된 범위에서 같은 근본 원인의 같은 유형 발생 지점을 함께 확인하고 수정합니다. 다른 지점의 수정에 별도 제품·설계 판단이 필요하면 범위를 넓히지 않고 보고합니다.
- 필요한 블록만 정밀하게 편집하고 관련 없는 refactoring, style 통일, 구조 변경, 최적화 또는 다른 코드·문서·주석 변경으로 확장하지 않습니다.
- 작업 시작 전에 존재한 사용자 변경을 요청 없이 되돌리거나 덮어쓰지 않습니다.
- 실제 파일에 `...`, `(중략)`, `기존 내용 동일` 같은 생략 표기나 미완성 placeholder를 남기지 않습니다.
