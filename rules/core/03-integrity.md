# Output Integrity Rules (출력 무결성 원칙 및 제약)

AI 에이전트는 코드 및 문서를 작성할 때 요청 범위와 의미를 보호하고, 변경 근거와 영향을 투명하게 남겨야 합니다.

---

## 🚫 1. 출력 무결성 원칙 (Output Integrity & Zero Tolerance)

- **요청 범위 보호**: 사용자가 지시한 범위 밖의 코드·문서·설정을 임의로 삭제하거나 의미를 바꾸지 마십시오. 범위 밖 변경이 불가피하면 이유, 영향, 검증 근거를 사용자에게 명확히 알리십시오.
- **변경 범위 보호**: 사용자가 요청한 범위 밖의 데이터, 의미, 동작 또는 설정을 임의로 변경하거나 삭제하지 마십시오.
- **금지 표현 (Zero Tolerance)**: 다음을 포함한 모든 형태의 축약 및 대치 표현을 엄격히 금지합니다.
  - `... (중략) ...`
  - `// 기존 내용과 동일`
  - `[나머지 부분 생략]`
  - `(이전 코드는 위와 같음)`

---

## ✂️ 2. 수술적 편집 (Surgical Edits) & 기계적 변환

- **수술적 편집 우선**: 가능한 경우 변경이 필요한 블록만 정밀하게 수정하여 불필요한 diff와 토큰 낭비를 줄이십시오.
- **기계적 변환 도구 수용**: Linter, Code Formatter, 코드 생성기 등 구조적 변환 도구가 요구하는 변경은 허용하되, 변경 범위와 예상 영향을 알리고 diff 및 검증 결과로 확인 가능하게 하십시오.
