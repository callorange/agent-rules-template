# Plan Refiner

사용자가 정한 목표와 제약을 유지하면서 기존 계획의 근거·접근법·검증 수준을 높입니다.

## 입력과 목표

사용자 요청, 현재 계획, 관련 프로젝트 지침을 확인합니다. 이미 확인된 정보를 재사용하고, 현재 계획이 없으면 검토할 계획이 필요하다고 알립니다.

계획의 산출물이 어떤 최종 결과를 위한 것인지 확인합니다. 그 결과에서 역으로 필요한 조건과 단계의 의존 관계를 살펴봅니다. 사용자가 정하지 않은 상위 목표를 새 요구사항으로 만들지 않습니다.

## 네 가지 심화 질문

### 1. 전문가라면 무엇을 더 할까요?

해당 분야의 숙련된 전문가라면 현재 요청이나 계획에 없는 어떤 조사·분석·실행을 할지 제안합니다.

전문가 역할을 연기하거나 추상적인 품질 표현을 늘리지 말고, 구체적인 행동과 그것이 결과를 개선하는 이유를 설명합니다.

### 2. 어떤 원자료부터 확인할까요?

이미 요약·해석된 정보 대신 어떤 코드·설정·기록·데이터·원문을 확인해야 중요한 가정을 검증할 수 있는지 제시합니다.

자료마다 확인할 질문과 접근 가능 여부를 연결합니다. 제안의 채택 여부를 판단하는 데 필요한 자료만 확인하고, 원자료라는 이유만으로 더 정확하거나 적합하다고 가정하지 않습니다. 실제로 확인한 사실과 아직 확인하지 못한 가정을 구분합니다.

### 3. 어떤 방법과 도구를 사용할까요?

목표와 자료에 맞는 구체적인 조사·분석·구현 방법을 제시합니다. 사용할 도구, 선택 이유와 얻을 결과를 연결합니다.

프로젝트의 기존 도구와 관례를 우선합니다. 기법의 이름을 나열하거나 전문적으로 보이기 위한 도구·의존성·계층을 추가하지 않습니다.

### 4. 무엇이 결과의 정확성을 보여줄까요?

에이전트와 사용자의 주관적 동의 외에 결과를 지지하거나 반박할 증거를 제시합니다.

테스트·재현·측정·기준 자료와의 대조 등에서 관찰할 결과와 확인 방법을 연결합니다. 다른 에이전트의 동의만으로 정확성이 입증되었다고 보지 않으며, 제안한 검증과 실제 실행한 검증을 구분합니다.

## 계획에 반영할 내용 선별

제안마다 다음을 판단합니다.

- 현재 목표의 정확성이나 성공 가능성을 높이는가?
- 기존 계획이 이미 해결하고 있지는 않은가?
- 추가 비용에 비해 얻을 증거와 효과가 있는가?
- 현재 범위와 권한 안에서 수행할 수 있는가?

근거가 부족한 제안은 확정 사항으로 바꾸지 않습니다. 목표·제품 동작·공개 계약 등을 바꾸는 제안은 필요한 사용자 결정과 함께 별도로 제시합니다.

자료 접근이나 외부 작업이 필요하다는 사실을 그 작업에 대한 승인으로 해석하지 않습니다.

## 보완 결과

다음 내용을 작업에 맞는 간결한 형식으로 반환합니다.

- 네 질문에 대한 답과 근거 또는 미확인 사항
- 채택·제외한 보완점과 그 이유
- 채택한 내용을 반영한 실행 가능한 보완 계획
- 기존 계획과 달라진 부분
- 검증 방법, 실패 시 재확인 대상과 종료 조건

보완 계획에는 검증 실패 시 관찰된 결과에 따라 관련 가정이나 단계를 재검토하는 경로를 포함합니다. 같은 검토를 무조건 반복하도록 하지 않습니다. 성공 증거 충족, 사용자 결정 필요, 외부 접근 차단, 새 근거 없는 반복을 구분하여 실행의 종료·중단 조건을 정합니다.

이 스킬의 완료는 보완 계획과 남은 미확인 사항을 반환하는 것입니다. 계획에서 제안한 미래의 실행·검증을 이미 완료한 것으로 보고하지 않습니다. 추가 가치가 없으면 “보완 불필요”와 이유를 반환합니다. 구현이나 파일 반영은 별도로 요청받은 경우에만 수행합니다.

## 설계 참고
