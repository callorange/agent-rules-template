# 의미적 정합성 권고 진단

규칙 원본의 conflict, behavioral ambiguity, over-prescription, scope 또는 authority 문제를 근거와 함께 검토합니다. 단일 키워드나 더 명확하게 쓸 수 있다는 이유만으로 advisory를 만들지 않습니다.

## 진단 기준

1. **상호 충돌**: Core와 하위 규칙, 또는 guide와 실제 rule·harness 정책이 정면으로 충돌하는가?
2. **행동상 모호성**: 둘 이상의 합리적인 해석이 실제 행동 차이를 만들고 주변 문맥으로 해소되지 않는가?
3. **중복과 drift**: 동일한 규범이 여러 모듈에서 독립적으로 정의되어 서로 달라질 현실적인 위험이 있는가?
4. **Authority와 scope**: 비규범 guide가 rule보다 우선하거나, 특정 범위의 지시가 전체 작업으로 확대·축소되게 하는가?
5. **아티팩트 격리**: 내부 메타 자산이 배포되거나 generated artifact가 source of truth로 취급되는가?
6. **과잉 처방과 ROI**: 구체적 실패 근거 없이 특정 implementation, 반복 검토, skill 또는 subagent 절차를 범용 의무로 고정하는가?

각 후보는 현재 구조가 이미 해결하는지, 실제 실패가 의미 있게 발생할 수 있는지, 더 작은 해결책이 있는지 반증합니다. 반증 후에도 남은 문제만 파일·현재 문구·행동 영향·최소 수정 방향과 함께 보고합니다.

## Guides 경계

`guides/`는 비규범적 참고 자료입니다. `권장한다`, `상황에 따라`, `예를 들어`, `고려할 수 있다` 같은 설명적 표현만으로 문제를 만들지 않습니다.

다음처럼 실제 행동 차이를 만드는 경우에만 advisory 대상이 됩니다.

- 같은 guide 안의 충돌
- guide가 `AGENTS.md` 또는 `rules/`보다 우선한다고 오해시키는 설명
- 예시나 재사용 패턴을 Hard Rule처럼 서술
- rule 또는 harness 정책과의 명백한 모순
- 특정 implementation을 범용 의무로 과도하게 처방

## 보고

이 진단은 독립 검토의 필요 여부나 구현 수단을 결정하지 않습니다. 독립 검토도 요구되는 작업에서는 같은 진단을 반복하지 않고, 이 rubric과 작업 목적, 변경 diff, 기계 검증 결과 및 잔여 위험을 해당 검토 수단에 제공합니다.

결과는 오류가 아닌 권고 보고서로 제시하며, 수정이 필요하면 사용자의 요청 범위와 승인 경계 안에서 반영합니다.
